# 《斗罗大陆人生模拟器》网页版 — 设计规格

> 日期：2026-08-10
> 状态：已与用户确认（DeepSeek + 极简沉浸式 + 核心循环完整版 + 后端权威状态）

## 1. 概述

将用户提供的《斗罗大陆人生模拟器》文字 RPG 规则书实现为可运行的网页游戏。AI（DeepSeek）担任旁白、NPC、世界演化引擎与系统裁决者；后端（FastAPI）担任权威账本，负责追踪并校验所有数值状态；前端（Vue3）做成极简沉浸式的全屏剧情流界面。

### 三个已确认的关键决定

1. **模型 API**：DeepSeek（`deepseek-chat`，流式）
2. **界面风格**：极简沉浸式 —— 全屏剧情文本、类阅读器、状态栏折叠、选项为胶囊按钮
3. **范围**：核心循环完整版 —— 角色创建 + 开放探索 + AI 叙述/选项 + 实时状态追踪 + 存档读档

### 核心架构决策

**后端权威状态 + AI 只管讲故事（混合架构）**
- 后端是状态唯一权威（魂力/金币/好感度/魂环/位置/日期）
- 每轮 AI 返回叙述文本 + 结构化「状态变动单」（state delta）
- 后端校验并应用变动单，触发被动机制（好感度衰减、自动存档），生成状态栏
- AI 负责裁决剧情，后端负责记账

## 2. 技术栈

| 层 | 技术 |
|---|---|
| 前端 | Vue 3 + Vite + Tailwind CSS，SSE 流式渲染打字机效果 |
| 后端 | Python + FastAPI + `openai` SDK（base_url 指向 DeepSeek） |
| 存储 | JSON 文件（`data/saves/<session_id>/` 下 state.json / history.jsonl / savepoints/） |
| 配置 | `.env`：`DEEPSEEK_API_KEY`（与现有校园项目同款 Key，独立 .env） |

## 3. 架构与数据流

```
前端 (Vue3 极简沉浸式)
  ├─ 角色创建向导（5轮分步表单 + 档案卡）
  ├─ 游戏主界面（剧情流 / 选项按钮 / 折叠状态栏 / 自由输入）
  └─ 存档面板（存档 / 读档 / 新开局）
        │  SSE 流式
后端 (FastAPI)
  ├─ 路由：/api/new-game  /api/act  /api/save  /api/load  /api/saves
  ├─ 状态引擎（权威账本 + 变动单校验 + 好感衰减 + 被动存档）
  ├─ 提示词组装器（规则书 + 当前状态 + 历史）
  ├─ DeepSeek 客户端（流式）
  └─ 存档管理（JSON 快照）
        │  磁盘
  data/saves/<session_id>/
    state.json      ← 权威状态
    history.jsonl   ← 完整对白记录（台词本地基）
    savepoints/     ← 存档快照
```

### 每轮数据流

1. 前端点击选项或输入自由行动 → `POST /api/act`
2. 后端组装消息：系统提示（规则书）+ 当前状态摘要 + 最近约 30 轮历史 + 本轮行动
3. DeepSeek 流式返回叙述文本，结束时给出结构化 JSON。`state_delta` 使用**固定英文键名**（由系统提示严格规定，避免 AI 变体导致解析失败）：
   ```json
   {
     "narrative": "叙述文本…",
     "options": [ {"label": "A", "text": "上前搭话——可能耽误正事"} ],
     "state_delta": {
       "gold": -5, "silver": 0, "copper": 0,
       "soul_level": 22,
       "affection": {"tang_san": 3},
       "location": "索托城·猫鹰酒店",
       "date": "第3年6月",
       "inventory_add": ["一壶酒"],
       "notes_add": ["得知大斗魂场连胜有奖金"]
     },
     "event": "触发的随机事件简述（可为空）"
   }
   ```
   固定的 delta schema（`gold/silver/copper/soul_level/affection/location/date/inventory_add/notes_add`）由后端 Applier 逐字段解析；键名映射表在实现时定义到 `backend/game/state_schema.py`。
4. 后端校验变动单 → 应用 → 计算好感衰减、检查自动存档 → 将叙述流 + 最终状态推给前端
5. 前端打字机渲染，叙述结束后浮现选项按钮

## 4. 权威状态模型（state.json）

```jsonc
{
  "character": {
    "name": "…", "gender": "…", "age": 12,
    "wuhun": "蓝银草", "innate_soul_power": 7, "soul_level": 22,
    "talent_tier": "天才档",
    "origin": "诺丁城·平民",
    "personality": ["沉稳","重义","多疑"],
    "traits": "外貌2-4关键词",
    "secret": "背负为家族复仇的执念"
  },
  "soul_rings": [
    {"slot": 1, "years": 423, "beast": "百年曼陀罗蛇", "skill": "缠绕"}
  ],
  "location": {"place": "索托城·猫鹰酒店", "season": "夏", "date": "第3年6月"},
  "resources": {"gold": 128, "silver": 3, "copper": 7},
  "affection": {"唐三": 12, "小舞": 8, "戴沐白": 0},
  "faction": {"武魂殿": 0, "七宝琉璃宗": 0, "史莱克学院": 0},
  "inventory": ["神秘地图"],
  "notes": ["索托大斗魂场规则：连胜有奖金"],
  "meta": {"turn": 47, "rewind_left": 3, "achievements": [], "direction": "自由/综合向", "timeline_binding": "半绑定"}
}
```

- 关键 NPC 好感度在开局时**预置键**（唐三/小舞/戴沐白/朱竹清/奥斯卡/宁荣荣/弗兰德/玉小刚/比比东/千仞雪/胡列娜）
- 重型系统（回溯/成就/派系声望复杂规则）**只占位、v1 不实现逻辑**
- 状态文件可读、可备份，便于后续扩展

## 5. 提示词组装（Prompt Builder）

- **系统提示**：完整游戏规则书（用户提供的那套规则全文，存储为 `backend/prompts/system_prompt.txt`）+ 斗罗世界设定要点 + 输出 JSON 格式约束 + 文风硬性规定（禁用套路句式、选项有人味、每轮结尾给 3-4 个选项等）
- **每轮组装**：`当前状态摘要 + 最近历史 + 玩家行动`。历史保留最近约 30 轮，更早的归档进 history.jsonl（台词本）不参与生成，控制 token
- 创建开局时：组装初始世界状态 + 开场白提示

## 6. 状态变动单校验与兜底（Delta Applier）

AI 会偶尔给错数字，三层保险：

1. **合法性校验**：
   - 金币/银币/铜币非负整数
   - 好感度钳制在 -100~100
   - 魂力每次增长幅度受限（如单轮 +0~2，突破大阶位需配合魂环事件），防止 AI 一次 +8
   - 魂环只能按 slot 顺序添加，禁止跳环；开局禁止直接带魂环
2. **解析兜底**：JSON 损坏 → 自动重试一次（要求严格格式）→ 仍失败则**只保留叙述文本**，本轮状态不动，不崩游戏
3. **被动机制后端算**：好感度衰减（长期不见面按游戏内日期每月 -1~2）、自动存档条件，由后端计算而非 AI

## 7. 角色创建向导（前端分步表单）

对应规则书五轮，做成表单（非 AI 问答，省 token、体验快）：

| 步 | 内容 | 选项要点 |
|---|---|---|
| 1 你是谁 | 身份类型 + 姓名/性别/出身 | 穿越者 / 原著重生 / 原创 / 自定义 |
| 2 来处与秘密 | 家庭状况 / 家族背景 / 执念或秘密 | 自由填 + 预设关键词 |
| 3 你的特质 | 外貌关键词 + 性格词 + 变强渴望(0-10) | 自由填 |
| 4 武魂与天赋 | **先选天赋档** → 按档生成先天魂力与武魂品质；武魂自选/自定义 | 凡人1-3 / 普通4-6 / 天才7-9 / 怪物9-10 |
| 5 初始财富 | 按出身给初始金币 + 特殊物品选择 | 平民5-10 / 小家族100-300 / 宗门500+ |

- 每步保留"自定义"入口
- 完成后生成**角色档案卡**确认 → `POST /api/new-game` → DeepSeek 写开场白
- 规则书天赋强度锚定约束直接内置于表单逻辑（怪物档也不能开局满环/超常规）

## 8. API 路由

| 路由 | 方法 | 说明 |
|---|---|---|
| `/api/new-game` | POST | 接收档案卡 → 初始化状态 → 生成开场白（SSE） |
| `/api/act` | POST | 玩家行动 → AI 叙述 + 状态变更（SSE） |
| `/api/save` | POST | 主动存档 |
| `/api/load` | POST | 读档 |
| `/api/saves` | GET | 存档列表（含时间线简述） |
| `/api/delete` | POST | 删除存档 |
| `/api/notes` | GET | 笔记/台词本查询 |

## 9. 前端界面

- **游戏主界面**：全屏深色背景剧情流，SSE 打字机逐字渲染
- **选项**：叙述结束后浮现 3-4 个胶囊按钮，点击即行动；底部自由输入框（自定义行动 / 快捷指令：存档、查看笔记、快进到X、切换方向）
- **状态栏**：右上角 ☰ 折叠展开，展开显示完整状态栏（姓名/性别/年龄/魂力/武魂/先天魂力/地点/季节/魂环配置/魂技/财富/势力声望/好感度/特殊状态/成就）
- **创建向导**：深色毛边纸风格分步表单 + 档案卡确认页
- **存档面板**：存档点列表（时间线简述）、读档/覆盖/新开局
- 响应式，手机竖屏可用

## 10. 存储与存档

- 每会话一文件夹 `data/saves/<session_id>/`：`state.json` + `history.jsonl` + `savepoints/`
- 存档点快照 = 状态 + 历史 + 笔记（规则书"查看存档列表 / 继续游戏"直接实现）
- 被动存档：每场战斗前 / 重大决策 / 每 10 轮自动存
- 主动存档：玩家输入"存档"指令
- 恢复：`继续游戏` → 读最近存档

## 11. 错误处理

- DeepSeek 超时/断流 → 自动重试一次 → 仍失败给友好提示，不丢已产生的叙述
- 历史过长 → 保留最近约 30 轮 + 权威状态摘要；更早归档进台词本
- 状态校验失败字段 → 丢弃该字段，保留 narrative

## 12. 范围边界（v1 明确不做，留扩展位）

| 不做 | 替代方案 |
|---|---|
| 魂环年限上限硬校验表 | AI 在系统提示中按规则书约束 |
| 回溯机制 | 状态占位（rewind_left），不实现 |
| 成就系统 | 状态占位（achievements），仅记录 |
| 战斗数值模拟（伤害公式） | AI 叙述战斗，后端只记魂力/状态 |
| 派系声望复杂逻辑 | 仅追踪数值，交互由 AI 叙述 |
| RAG 知识库 | 后续需要更懂原著细节时再加 |
| 多模型切换 | 客户端抽象，v1 仅 DeepSeek |

## 13. 规则书集成

- 用户提供的完整游戏规则（核心原则、地图、开局身份、方向、角色创建、核心机制、世界演化、辅助功能、文风约束、世界观扩展、天赋锚定、补充设定、输出格式）整体作为系统提示词底座，存储于 `backend/prompts/system_prompt.txt`
- 文风硬性规定（禁套路句式、选项有人味、150-250字叙述、每轮选项结构）必须原样进入系统提示
- 输出格式约束（状态栏代码块、选项【A】、【B】分隔线等）由前端渲染层处理，AI 输出 JSON 结构而非文本格式
